# คืนบางส่วนและประวัติการทำงาน

- หน้าคืนให้กรอกจำนวนปกติ ชำรุด สูญหาย และผิดปกติ รวมกันได้ตั้งแต่ 1 ถึงจำนวนค้างคืน รองรับหลายครั้งและหลายสภาพในครั้งเดียว
- จำนวนปกติเพิ่มพร้อมยืม ชำรุด/ผิดปกติเพิ่มรอซ่อม สูญหายไม่เพิ่มสต็อก
- แยกส่วนที่คืนออกเป็นแถวสถานะ returned ที่อ้างอิง parent_loan_id เดิม แต่ละแถวมีสภาพ จำนวน วันคืน ผู้บันทึกคืน และสถานะซ่อมของตัวเอง แถวต้นทางยังเป็น borrowed ตามจำนวนคงเหลือ จนคืนครบ
- original_quantity บนรายการต้นทางเก็บจำนวนยืมเดิม quantity คือจำนวนของแต่ละส่วน ผลรวม quantity ของต้นทางและส่วนที่คืนเท่ากับจำนวนยืมเดิมเสมอ ห้ามนำ original_quantity ของทุกแถวมารวมเป็นยอดยืม
- API ส่ง rootLoanId สำหรับจัดกลุ่ม หน้าประวัติแสดงหมายเลขต้นทาง รายงานส่งออกแยกแถวตามส่วนที่คืน จึงนับจำนวนได้โดยไม่ซ้ำ รายการเก่ายังคงอยู่และไม่มีการแต่งข้อมูลผู้บันทึกย้อนหลัง
- ผู้บันทึกคืนหมายถึงบัญชีที่กดบันทึก ไม่ได้ยืนยันว่าเป็นผู้ส่งมอบของจริง และยังไม่มีขั้นตอนเจ้าหน้าที่ตรวจรับ (ไม่อยู่ในงานนี้)

## ประวัติการทำงาน

เมนูประวัติการทำงานมีเฉพาะผู้ดูแล ค้นหาชื่อผู้ทำรายการหรือรหัส กรองประเภท และโหลดครั้งละ 50 รายการได้ บันทึกการเพิ่ม/แก้ไข/ลบอุปกรณ์ การยืม การคืน การปิดงานซ่อม การแก้กำหนดคืน บัญชีและโปรไฟล์ พร้อมค่าก่อน–หลังและชื่อผู้ทำรายการ ณ เวลานั้น

Trigger บันทึก audit_logs ใน transaction เดียวกับการแก้ข้อมูล หากบันทึกประวัติไม่สำเร็จ การแก้ข้อมูลถูก rollback ด้วย ไม่เก็บรหัสผ่าน Google subject หรือเนื้อหารูปภาพในประวัติ ไม่มี API แก้ไขหรือลบประวัติ ข้อมูลที่เปลี่ยนโดยตรงในฐานข้อมูลโดยไม่กำหนด actor จะระบุว่าเป็นระบบ/ไม่ระบุผู้ทำรายการ

## เปิดใช้และทดสอบ

server.js ใช้ migration 011_partial_returns_audit.sql อัตโนมัติเมื่อเริ่มเซิร์ฟเวอร์ เก็บ original_quantity ให้รายการเดิม และเริ่ม audit เฉพาะเหตุการณ์ใหม่ ต้องอัปเดต backend พร้อม frontend

```
npm test
docker compose build app
docker compose run --rm -e DB_INTEGRATION=1 app node --test test/returns-audit.integration.test.js
docker compose up -d app
```

Integration test ใช้ schema ชั่วคราวแยกจากข้อมูลจริงและลบเฉพาะ schema ทดสอบเมื่อจบ ครอบคลุมคืนผสม/บางส่วน คำขอซ้ำ คำขอพร้อมกัน สิทธิ์ ยอดคลัง การซ่อม และ rollback เมื่อ audit ล้มเหลว

POST /api/loans/:id/return รับ quantities เช่น {normal:2,damaged:1} และ requestId (UUID) เพื่อป้องกันการบันทึกซ้ำเมื่อส่งคำขอเดิมอีกครั้ง โดยคำขอเดิมต้องมี payload เดิม UI สร้าง requestId ต่อหนึ่งฟอร์มและปิดปุ่มระหว่างส่ง
