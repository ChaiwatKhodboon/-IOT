# กระบวนการคืนและตรวจรับ

1. ผู้ยืมส่งจำนวนแยกตามสภาพ ระบบขึ้นรอตรวจรับและยังไม่เปลี่ยนสต็อกหรือยอดค้างคืน
2. Admin เปิดติดตาม > รอตรวจรับ > ตรวจรับคืน ปรับจำนวนและสภาพตามของที่ได้รับจริง
3. ยืนยันตรวจรับจึงเพิ่มของปกติกลับสต็อก ส่งของชำรุด/ผิดปกติไปรอซ่อม และบันทึกสูญหาย
4. จำนวนที่ไม่ได้ตรวจรับยังค้างคืน ผู้ใช้ส่งคำขอใหม่ได้หลังตรวจรับครั้งนี้
5. ส่งกลับให้แก้ไขต้องระบุเหตุผล ผู้ใช้เห็นเหตุผลและส่งใหม่ได้ สต็อกไม่เปลี่ยน

Admin ตรวจรับหน้าเคาน์เตอร์ได้โดยไม่ต้องมีคำขอก่อน ถือเป็นการตรวจรับโดยเจ้าหน้าที่โดยตรง
ระหว่างรอตรวจรับยังใช้กำหนดคืนเดิมและยังนับเกินกำหนดตามเดิม
บันทึกผู้แจ้งและเวลาไว้ใน pending_return และ audit_logs ผู้ตรวจรับอยู่ใน returned_by

## API
POST /api/loans/:id/return: User ได้ 202 และ status=pending_return; Admin ได้ 200 หลังตรวจรับ
Admin ต้องส่ง inspectionId ตรงกับ pendingReturn.id เมื่อมีคำขอค้างอยู่ หากคำขอเปลี่ยนคืน 409
POST /api/loans/:id/return/reject: Admin ส่ง inspectionId และ reason
GET /api/loans?status=pending_return: คำขอรอตรวจรับตามสิทธิ์
requestId เป็น UUID สำหรับป้องกันบันทึกซ้ำ ใช้ค่าใหม่เมื่อส่งคำขอใหม่

## ติดตั้ง
เซิร์ฟเวอร์รัน migration 012_return_inspection.sql อัตโนมัติเมื่อเริ่มใหม่
